\section{Method}

This paper uses a reflective single-case study based on the Sanguine opportunity sets, project charter, architecture assignments, uncertainty analysis, development planning work, project model, risk analysis, final presentation materials, and executive memo completed in the MIT SDM core \cite{sanguine_charter,sanguine_os9,sanguine_os11,sanguine_os13,sanguine_os14,sanguine_os15,sanguine_os16,sanguine_os17,sanguine_memo}. The case was selected because it contains a complete sequence from problem framing to executive recommendation.

The analysis follows the project chronologically, but the paper reorganizes the material around six design questions:

\begin{enumerate}
    \item What is the system boundary?
    \item Which stakeholders define value and feasibility?
    \item Which architecture decisions drive performance, cost, and governance?
    \item How do uncertainty and risk change the preferred architecture?
    \item What development approach fits the lifecycle risks?
    \item What baseline should leadership authorize?
\end{enumerate}

The source material includes numerical models and estimates. Those numbers should be read as planning estimates, not as audited financial or clinical results. Their purpose in this paper is to show how relative decisions changed under different assumptions.
